Gotcha WebSocket API 1.0.0
  • application/json
  • ID: gotcha:websocket-api

이 문서는 Gotcha 게임 플랫폼의 실시간 WebSocket(STOMP) 통신 명세서입니다. SockJS를 통해 WebSocket 연결을 시도합니다.

주체 동작 사용하는 STOMP 함수 경로 예시
클라이언트 → 서버 메시지 보냄 stompClient.send() /pub/**
서버 → 클라이언트 메시지 보냄 stompClient.subscribe() /sub/**

⭐[도메인 채널 prefix]

본 서비스는 총 4개의 메시지 전송 경로(prefix)를 사용하며, 구체적인 로직 분기는 경로가 아닌 DTO 필드로 구분됩니다.

  • /pub/room/{roomId} : 대기방 관련 로직들 (대기방 내 채팅 포함)
  • /pub/chat/** : 채팅 관련 로직들 (전체 채팅 및 개인 채팅)
  • /pub/game/{roomId} : 게임 관련 로직들
  • /pub/lobby/** : 로비 관련 로직들

⭐[에러 채널]

  • 대기방 에러 채널 : /user/room/errors/{userUuid}
  • 로비 에러 채널 : /user/lobby/errors/{userUuid}
  • 채팅 에러 채널 : /user/chat/errors/{userUuid}
  • 게임 에러 채널 : /user/game/errors/{userUuid}
  • 기본 에러 채널 : /user/queue/errors/{userUuid}

Servers

  • http://43.203.244.35:8080/ws-connectwsproduction

    SockJS 기반 STOMP WebSocket 연결을 지원합니다. 기본적으로 WebSocket(ws) 사용, 실패 시 HTTP long-polling 등 으로 fallback 됩니다. 핸드쉐이크 시, 반드시 HTTP 헤더에 Authorization: Bearer {JWT 토큰} 를 포함해야 합니다.

    • ROUND_START: 라운드의 시작을 알립니다.

      • 클라이언트에서는 drawerUuid 필드와 imageURL 필드를 확인해 그림을 그린 플레이어와 그림을 맞출 플레이어를 구분할 수 있습니다.
    • GUESS_REQUEST: 추측 요청 브로드캐스트입니다.
      • payload의 data 필드에는 추측을 위한 메타정보인 guess 데이터가 전송됩니다.
      • guesserUuid 필드가 AI인 경우 잠시 후 AI 추측결과가 GUESS_SUBMIT으로 함께 브로드캐스트 됩니다.

    • GUESS_SUBMIT: 추측 데이터 제출 브로드캐스트입니다.
      • 해당 턴의 추측 데이터 제출 시 이를 브로드캐스트 합니다.
      • payload의 data 필드에는 Guess 데이터가 전송됩니다.
    • GUESS_RESULT: 추측 결과를 클라이언트에 브로드캐스트합니다.
